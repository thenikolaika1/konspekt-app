# Аналитика Konspekt (P0, Friends & Family)

## Где смотреть

Supabase Dashboard → проект → **SQL Editor** → вставить запрос из [`reports.sql`](reports.sql) → **Run**.
Удобно сохранить шесть запросов как сниппеты («1 Пользователи» … «6 Сводка»): тогда каждый отчёт
открывается одним кликом. Отчёты доступны только владельцу проекта: схема `analytics` закрыта для API,
приложение и пользователи их не видят.

| № | Отчёт | Запрос | Одна строка |
|---|---|---|---|
| 1 | Пользователи | `select * from analytics.r1_users;` | анонимный ID |
| 2 | Посещения | `select * from analytics.r2_views;` | сессия просмотра параграфа |
| 3 | Популярные параграфы | `select * from analytics.r3_paragraphs;` | материал библиотеки |
| 4 | По дням | `select * from analytics.r4_daily;` | день по Москве |
| 5 | AI-генерации | `select * from analytics.r5_ai;` | запуск генерации с вызовом AI |
| 6 | Сводка | `select * from analytics.r6_summary;` | показатель (всё время / F&F / сегодня / 7 дней) |

Только F&F (12–18.10.2026 по Москве): `where in_ff` в отчётах 2, 4, 5; даты берутся из `private.ai_limits`.

## Что означают показатели

- **User ID** — анонимный аккаунт Supabase в одном браузере/PWA. Другое устройство, очистка данных,
  инкогнито или переустановка PWA дают новый ID. Это не число людей.
- **Открытие приложения** — запуск (`app_cold`) или возврат после ≥ 30 мин в фоне (`app_resume`).
  Обновление токена открытием не считается.
- **Открытие библиотеки** — переход в раздел «Библиотека» из другого раздела.
- **Сессия просмотра** — непрерывное пребывание на экране параграфа; фон до 30 мин — та же сессия.
- **Приблизительное активное время просмотра** — время, когда экран параграфа виден и с последнего
  касания, прокрутки или клавиши прошло не больше 120 с. Фон, блокировка экрана, бездействие и закрытое
  приложение не считаются. На сессию — не больше 60 мин, на пользователя — не больше 6 ч в сутки.
  Это оценка, а не доказательство чтения.
- **Дни и полночь** — открытие относится ко дню открытия; активное время — ко дню, когда сервер его
  получил (отправка раз в минуту), поэтому сессия через полночь делится между днями с точностью ~1 мин.
- **Активный ID за день** — открыл приложение или библиотеку, смотрел параграф или запускал AI.
- **Вернувшийся** — активен в день позже своего первого активного дня; «со вчера» — активен и вчера, и сегодня.
- **AI** — строка `ai_generations` пишется, только если вызывался AI. Отказы до вызова AI (нет права,
  лимит, больше 4 страниц, AI выключен) и коды ошибок туда не попадают — только в логи Edge Function.
- **Стоимость AI** — `NULL` / `UNKNOWN`, пока не задана цена (`PRICE_PER_M = 0` в analyze-pages пишет 0,
  это «не известно», а не «бесплатно»).

## Управление

- Выключить сбор (данные сохраняются): `revoke execute on function public.track(jsonb) from authenticated;`
  и/или `analytics: false` в `js/config.js`. Включить снова: `grant execute on function public.track(jsonb) to authenticated;`
- Новый материал в библиотеке: `node tools/catalog-to-sql.mjs > supabase/migrations/<время>_analytics_catalog.sql`
  и применить. Неизвестные серверу параграфы не записываются.
- Удаление пользователя (auth.users) удаляет и его события.
- Хранение: рекомендуется не дольше 180 дней. Удаление старых данных — только вручную и осознанно, например:
  `delete from analytics.paragraph_views where opened_at < now() - interval '180 days';`
  `delete from analytics.app_events where created_at < now() - interval '180 days';`
