# v65: подарок «Только ИИ-генерации»

## Что это
В панели владельца у подарка теперь два типа:
1. **Дни доступа + ИИ** — прежний подарок, без изменений.
2. **Только ИИ-генерации** — новый: +N генераций к действующему доступу ученика, **без дней**.

Где: Панель → 🎁 Подарить доступ → «Тип подарка», или карточка ученика → «🤖 Подарить генерации»
(кнопка есть у ученика с пробным периодом, подарком или Premium).

## Правила (решение владельца, 07.11.2026)
- Генерации **прибавляются** к лимиту той выдачи, с которой ученик тратит генерации сейчас
  (`private.active_grant` — та же, что при запуске ИИ): пробный период, подарок или Premium. Было 3 доступно, +5 → 8.
- Срок, тариф, другие выдачи и уже использованные генерации **не меняются**. Premium не включается, пробный не продлевается.
- Генерации действуют, **пока действует эта выдача**, и сгорают вместе с ней — по прежним правилам.
- **Нет действующего доступа** (истёк, отозван) — выдача запрещена (`NO_ACTIVE_ACCESS`). ИИ без доступа не открывается.
- Владельцу (`GIFT_OWNER`) и старому ручному доступу F&F (`GIFT_MANUAL_ACCESS`) не выдаётся.
- За раз 1–100 генераций; итог в выдаче — не больше 1000 (ограничение таблицы).
- Бюджет ИИ: для Premium — как при выдаче срока (генерации входят в резерв Premium), для подарка и пробного —
  как при подарке (только из свободного бюджета). Не хватает — `BUDGET_LOW`, ничего не начисляется.
- Если у ученика после Premium уже ждёт будущий подарок, генерации добавятся к **текущему** Premium.

## Изменения Supabase
Миграция `supabase/migrations/20261107150000_v65_gift_ai_only.sql` — **только добавляет 4 функции**:
`private.panel_gift_ai_plan`, `private.panel_gift_ai_budget_check`, `public.owner_gift_ai_preview`, `public.owner_gift_ai`.
Таблицы, правила доступа, запуск и списание генераций, прежние функции панели — не меняются. Повторное применение
безопасно (`create or replace`). Данные учеников при установке не меняются (проверено: `tests/v65/run.sh`, M1).

Защита — как у остальных действий панели: только POST, сессия панели владельца, идемпотентность по `request_id`
(двойное нажатие и повтор после обрыва сети не начисляют второй раз), блокировка ученика, атомарное изменение,
журнал `access_log` (`gift_ai`: сколько, к какой выдаче, лимит было → стало) и журнал отказов. Внутренние функции
ролям API недоступны; `owner_gift_ai*` вызываются вошедшим пользователем, а права владельца проверяет сессия панели.

## Откат
Новый тип подарка можно убрать, вернув `js/owner.js` прежней версии. Функции можно оставить (без панели их никто не
вызывает) или удалить: `drop function public.owner_gift_ai(text, uuid, text, integer, text);
drop function public.owner_gift_ai_preview(text, text, integer); drop function private.panel_gift_ai_budget_check(text, text, integer);
drop function private.panel_gift_ai_plan(uuid, integer);` — уже начисленные генерации останутся в лимитах учеников.
