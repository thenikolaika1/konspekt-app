# v61.3: панель владельца — выпуск, первый вход, ежедневная работа

Ничего из этого не выполнено в production. Каждый шаг — только после отдельного решения владельца.
Панель работает поверх v61.2 (пробный период и платный доступ): сначала (или в том же окне) выпускается v61.2 — `paid-access-v61.md`.

## Как защищена панель

Панель открывается, только если сервер подтвердил **все четыре условия** — каждый раз, при каждом действии:

1. Ты вошёл в свой аккаунт (ID + ключ, Supabase Auth), и этот вход ещё действует. Выход из аккаунта закрывает панель.
2. У аккаунта есть роль «владелец» (`private.access_grants`, kind = owner). Её выдаёт только SQL Editor.
3. Введён **постоянный пароль панели**. В базе хранится только его bcrypt-отпечаток (`private.owner_panel_secrets`); сам пароль нигде не хранится — ни в приложении, ни в базе, ни в логах.
4. Действует **сессия панели**: случайный ключ (256 бит) выдаётся после пароля; в базе — только его отпечаток. Срок — 12 часов, без действий — 2 часа. Потом просто снова вводишь тот же пароль.

Перебор пароля: 5 неверных попыток подряд → пауза 15 минут, следующие серии → 1 час, 4 часа, 24 часа. Счётчик на сервере: перезагрузка страницы, другое устройство и параллельные запросы его не обходят. Все неверные попытки и паузы видны в «История».

Ученик не видит кнопку панели, а если вызовет функции панели вручную — сервер ответит «нет доступа» (проверено тестами для гостя, ученика и участника F&F). Ключ `service_role` в приложении не используется.

**Секреты — только в теле POST-запроса.** Пароль панели, код установки и ключ сессии приложение отправляет только методом POST (supabase-js): тело запроса ни PostgREST, ни шлюз Supabase в журналы не пишут. PostgREST умеет вызывать функции и через GET/HEAD — тогда аргументы оказываются в адресе запроса, а адреса попадают в журналы. Поэтому **каждая функция панели первой строкой отказывает на любом методе, кроме POST** (`METHOD_NOT_ALLOWED`) — даже с верным паролем ничего не выполняется (проверено тестами: 18 функций × GET и HEAD, через настоящий PostgREST). Ограничение, которое сервер снять не может: адрес уже отправленного кем-то GET-запроса шлюз запишет в журнал до базы — поэтому пароль никогда не вставляют в адрес; приложение так не делает (тоже проверено тестами). Старая функция `redeem_beta_invite(p_code)` (не используется) лишена права вызова.

## Выпуск (одно окно, после v61.2)

**Шаг 0. Предпроверка (только чтение, SQL Editor):**
```sql
select to_regclass('private.access_grants');        -- НЕ NULL: v61.2 уже применена
select to_regclass('private.owner_panel_secrets');  -- NULL: панель ещё не применялась
select to_regprocedure('extensions.crypt(text,text)') is not null;  -- true: bcrypt (pgcrypto) есть
```

**Шаг 1. Миграция панели.** Dashboard → SQL Editor → вставить **весь** файл `supabase/migrations/20261026120000_owner_panel.sql` → Run (один запуск). Проверка:
```sql
select count(*) from pg_proc p join pg_namespace n on n.oid = p.pronamespace where n.nspname = 'public' and p.proname like 'owner\_%';  -- 18
select has_function_privilege('authenticated', 'public.redeem_beta_invite(text)', 'execute');  -- false
select count(*) from private.invite_meta;   -- столько же, сколько строк в private.beta_invites
```
Сбой: файл — одна транзакция, при ошибке не создаётся ничего (проверено). Повторный запуск поверх применённой миграции отклоняется целиком.

**Шаг 2. Приложение** (в том же merge, что и v61.2, или следующим): `app.js`, `js/cloud.js`, `js/owner.js`, `owner.css`, `styles.css`. Файлы панели скачивает только владелец, по нажатию кнопки.

**Откат:** приложение — revert; база — блок «Откат» в конце файла миграции панели (удаляет только объекты панели; выдачи, приглашения и журнал остаются — проверено).

## Первый владелец (один раз)

1. **Приглашение для себя.** Пока панели нет — на компьютере: `node tools/ff-invite-codes.mjs --count 1 --quota 1 --label "владелец"` → выполнить напечатанный SQL в SQL Editor.
2. **Регистрация.** В приложении: «Ранний доступ» → код → «Создать аккаунт».
3. **Сохрани ID и ключ** (в двух местах). Потерянный ключ аккаунта не восстанавливается.
4. **Роль владельца** (SQL Editor): `select private.admin_set_owner('KN-ТВОЙID', 'владелец');`
5. **Код установки пароля** (SQL Editor): `select private.admin_panel_setup('KN-ТВОЙID');` → в ответе `setup_code` вида `ABCD-EFGH-JKMN`, действует **30 минут**, один раз, только для твоего аккаунта.
6. **Пароль.** Приложение → «Я» → **👑 Панель владельца** → «Проверить» → введи `setup_code`. Пароль генерируется прямо на телефоне (20 символов, `XXXXX-XXXXX-XXXXX-XXXXX`) — **сохрани его** (например, в «Пароли» iPhone), отметь «Я сохранил пароль» → «Установить пароль».
   Хочешь сгенерировать на компьютере: `node tools/owner-panel-password.mjs` → на экране установки «У меня пароль из генератора».
7. **Проверка прав** (SQL Editor): `select private.admin_status('KN-ТВОЙID') -> 'access' ->> 'status';` → `owner`.
8. **Проверка, что ученик не получает доступа:** войди учеником (или попроси ученика) — в «Я» нет кнопки панели.

Пароль панели — постоянный: он не меняется, пока ты сам его не сменишь. Не совпадает с ключом аккаунта (сервер это проверяет).

## Ежедневная работа (iPhone, без SQL)

Вход: «Я» → **👑 Панель владельца** → пароль (если сессия закончилась).

**Выдать подписку** (ученик заплатил за 30 дней и 20 генераций):
1. «Ученики» → поиск по ID (можно часть: `ABC`) → ученик → **«Выдать подписку»**.
2. Срок: 7 / 30 / 90 дней или «Свой»; генерации: число; комментарий (например, «оплата 26.10, 500 ₽»).
3. «Продолжить» → экран подтверждения: даты начала и окончания посчитал **сервер** → **«Подтвердить выдачу»**.
4. Результат показывается только после ответа сервера: срок, лимит, статус ученика. Двойное нажатие не выдаст вторую подписку.
Ученику достаточно свернуть и открыть приложение — в «Мой доступ» появится «Оплачен до …».

**Продлить:** карточка ученика → «Продлить» → срок и генерации → подтверждение.
Досрочное продление начинается **с конца текущего срока** (оплаченные дни не теряются); неиспользованные генерации текущего срока на новый не переносятся. Если пока ты смотрел подтверждение, срок ученика изменили — панель откажет («данные изменились») и попросит проверить заново.

**Отозвать:** карточка ученика → «Отозвать доступ» → панель покажет **все** действующие и будущие оплаченные сроки — **отзываются все сразу** (так работает `admin_revoke`) → введи последние 3 символа ID → «Отозвать доступ». Вернуть доступ — новой выдачей.

**Приглашение:** «Коды» → «Создать приглашение» → подпись (кому) и срок действия кода → «Создать код» → код показывается **один раз**: «Скопировать» или «Поделиться» (Telegram, сообщения). В базе — только отпечаток кода. Не больше **10 кодов в сутки** из панели.
Отзыв: в списке у активного кода — «Отозвать» (использованный отозвать нельзя; если по коду прямо сейчас идёт регистрация — подожди 15 минут).

**ИИ и бюджет:** остаток общего бюджета, состояние (работает / автостоп с причиной и временем «не позже» / бюджет исчерпан), ошибки за сутки, график за 7 дней. **Панель бюджет не меняет** — это по-прежнему SQL Editor (отдельное решение владельца).

**История:** выдачи, продления, отзывы, приглашения, отказы операций, события пароля панели — кто (панель / SQL Editor / автоматически) и когда.

## Восстановление и смена пароля

**Сменить пароль:** панель → ⚙ → «Сменить пароль» → текущий пароль → новый (генерируется) → сохрани → «Сменить пароль». Все сессии панели на других устройствах закрываются.

**Забыл пароль панели** (доверенная процедура, только SQL Editor):
```sql
select private.admin_panel_setup('KN-ТВОЙID');   -- старый пароль и все сессии панели перестают действовать
```
→ новый `setup_code` (30 минут) → в приложении «Установить пароль». Ученик сделать это не может: функция недоступна приложению.

**Потерял телефон** (пароль помнишь): `select private.admin_panel_revoke_sessions('KN-ТВОЙID');` — все сессии панели закрыты. Если кто-то мог узнать и пароль — сбрось его командой выше. Вход в аккаунт по ID+ключу на новом телефоне — как обычно.

**Потерял ключ аккаунта:** новый аккаунт по новому коду → `admin_set_owner` на новый ID → `admin_revoke('KN-СТАРЫЙ', 'потерян ключ', 'owner')` → пароль панели для нового ID (`admin_panel_setup`).

## Проверка безопасности (SQL Editor, только чтение)

```sql
-- функции панели: только для вошедших (authenticated), не для анонимных; внутренние — никому из ролей API
select p.proname, has_function_privilege('anon', p.oid, 'execute') anon, has_function_privilege('authenticated', p.oid, 'execute') auth
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace where n.nspname = 'public' and p.proname like 'owner\_%';
-- пароль хранится только отпечатком bcrypt; сессий без отзыва и срока нет
select user_id, left(password_hash, 4) as alg, password_set_at, locked_until from private.owner_panel_secrets;
select user_id, count(*) filter (where revoked_at is null and expires_at > now()) as active from private.owner_panel_sessions group by 1;
-- подозрительные события
select at, event, details from private.owner_security_log order by at desc limit 30;
```

## Что проверено и что — нет

Проверено локально (PostgreSQL 16 с имитацией Supabase, Chromium в размерах iPhone): вход и права (гость, ученик, F&F, владелец без пароля, неверный пароль, пауза, параллельные попытки, истечение, выход, смена и сброс пароля, отзыв роли), выдача/продление/отзыв с повтором и параллельными запросами, приглашения (одноразовость, срок, отзыв, дневной предел, параллельное создание, код не раскрывается), данные (список, поиск, страницы, история, ИИ, отсутствие секретов в ответах), миграция (транзакция, повтор, откат, данные v61 не меняются), интерфейс на 320–1280 px.

**Не проверено без настоящего Supabase и iPhone:**
- что функции базы (владелец `postgres`) читают `auth.sessions` в Supabase (используется, чтобы выход из аккаунта сразу закрывал панель) и что в JWT есть `session_id`;
- вызов функций через PostgREST (аргументы, ответы), время жизни JWT;
- что пароль не попадает в журналы Supabase (API-логи пишут путь и статус запроса, не тело; параметры запросов PostgreSQL в журнал не пишутся при стандартных настройках — проверить в Logs Explorer);
- Safari и установленное PWA: генерация пароля, «Поделиться», сохранение пароля в «Пароли», клавиатура при поиске.
