# v62: ручная проверка Premium UI на iPhone — тестовый режим (без production)

Production Supabase сейчас на v61.3: в нём нет тарифа Premium и функции библиотеки v62, а вход и аналитика писали бы
в production. Поэтому проверка идёт в **тестовом режиме**: сайт из ветки `feature/v62` с компьютера, а «сервер» — имитация
из автотестов (`tests/v61/stub-cloud.js`): статусы доступа, тариф (с ценой «299 ₽» в ответе — как в production до шага 2б,
интерфейс должен её скрыть) и тексты библиотеки — вымышленные. Адрес Supabase в настройках тестового режима пустой,
аналитика выключена: запросов к production нет. ID ученика в тестовом режиме: **KN-TEST42**.

Прошлый способ (`serve-konspekt.ps1`, v61.3) не подходит: он слушал только `localhost` (для сети на Windows нужен
администратор) и ходил в production.

## Запуск

На компьютере (Node.js уже есть), в папке репозитория:
```
git checkout feature/v62
git pull
node tools/premium-preview.mjs
```
Сервер напечатает адреса, например:
```
  На этом компьютере:  http://localhost:8765/konspekt-app/__preview/
  На iPhone (та же Wi-Fi): http://192.168.1.23:8765/konspekt-app/__preview/
```
На iPhone в Safari открыть **вторую** строку (свой IP; посмотреть вручную: `ipconfig` → «IPv4-адрес»).
- Windows спросит про брандмауэр для Node.js — разрешить **только «Частные сети»**. Сеть Wi-Fi в Windows должна быть
  «Частной». Гостевая Wi-Fi роутера часто не пускает устройства друг к другу — тогда подключиться к основной.
- Остановить сервер: `Ctrl+C` в окне. Пока он работает, тестовый сайт видят устройства этой Wi-Fi (только чтение,
  только файлы сайта, данные вымышленные).

На странице `__preview/` — 9 сценариев. Нажатие на сценарий стирает данные приложения **только на тестовом адресе** и
открывает приложение. Жёлтая метка «ТЕСТ · …» справа сверху — признак тестового режима; нажатие — снова выбор сценария.

## Что в тестовом режиме проверить нельзя (по HTTP в локальной сети Safari считает страницу небезопасной)
- **Service Worker** не работает: работа без сети и обновление со старой версии (v61.3 → v62) здесь не проверяются —
  они проверены автотестами (Chromium) и проверяются на опубликованном сайте (HTTPS, после выпуска).
- **Clipboard API** недоступен: «Скопировать ID» работает запасным способом (копирование выделенного ID) — тот же,
  что на старых iOS. Основной способ (Clipboard API) проверяется на опубликованном сайте.
