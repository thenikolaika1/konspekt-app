# v62: ручная проверка Premium UI — тестовый режим (Chrome на компьютере или iPhone), без production

Production Supabase сейчас на v61.3: в нём нет тарифа Premium и функции библиотеки v62, а вход и аналитика писали бы
в production. Поэтому проверка идёт в **тестовом режиме**: сайт из ветки `feature/v62` с компьютера, а «сервер» — имитация
из автотестов (`tests/v61/stub-cloud.js`): статусы доступа, тариф (с ценой «299 ₽» в ответе — как в production до шага 2б,
интерфейс должен её скрыть) и тексты библиотеки — вымышленные. Адрес Supabase в настройках тестового режима пустой,
аналитика выключена: запросов к production нет. ID ученика в тестовом режиме: **KN-TEST42**.

Прошлый способ (`serve-konspekt.ps1`, v61.3) не подходит: он слушал только `localhost` (для сети на Windows нужен
администратор) и ходил в production.

## Запуск — Chrome на этом компьютере (основной вариант)

PowerShell, в папке репозитория (Node.js уже есть):
```
git checkout feature/v62
git pull
node tools\premium-preview.mjs
```
Открыть в Chrome: **http://localhost:8765/konspekt-app/__preview/** (просто `http://localhost:8765/` тоже ведёт туда).
Сервер доступен только на этом компьютере. Остановить: `Ctrl+C` в окне PowerShell. Порт занят — `--port 8766`
(и адрес с 8766).

Изоляция от production (проверена тестом `tests/v62/preview.test.mjs` и в Chrome):
1. вместо `js/cloud.js` — имитация сервера, настоящий клиент Supabase не загружается;
2. в настройках нет адреса и ключа Supabase, аналитика выключена;
3. заголовок Content-Security-Policy разрешает браузеру запросы **только к localhost:8765** — запрос к `*.supabase.co`
   Chrome блокирует сам (видно в DevTools → Console как нарушение CSP; в DevTools → Network — только localhost).

**Переключение состояний Premium.** На странице `__preview/` — 9 сценариев (кнопки). Нажатие стирает данные приложения
на тестовом адресе и открывает приложение в выбранном состоянии. Жёлтая метка «ТЕСТ · …» справа сверху — какой сценарий
сейчас; нажатие на неё — снова к выбору. Сценарий сохраняется при обновлении страницы. Можно и адресом:
`http://localhost:8765/konspekt-app/?s=premiumExpired` (`trial`, `trialExpired`, `premium`, `premiumEnding`,
`premiumNoAi`, `premiumExpired`, `gift`, `giftExpired`, `plansError`).
Ширина телефона в Chrome: DevTools (F12) → значок телефона (Ctrl+Shift+M) → Dimensions: 390 × 844.
В Chrome на localhost работают основной способ «Скопировать ID» (буфер обмена) и service worker.

## Запуск для iPhone (та же Wi-Fi)

```
node tools\premium-preview.mjs --lan
```
Сервер напечатает адрес для iPhone, например `http://192.168.1.23:8765/konspekt-app/__preview/`.
- Windows спросит про брандмауэр для Node.js — разрешить **только «Частные сети»**. Сеть Wi-Fi в Windows должна быть
  «Частной». Гостевая Wi-Fi роутера часто не пускает устройства друг к другу — тогда подключиться к основной.
- Пока сервер работает с `--lan`, тестовый сайт видят устройства этой Wi-Fi (только чтение, только файлы сайта, данные
  вымышленные).

## Что на iPhone в тестовом режиме проверить нельзя (по HTTP в локальной сети Safari считает страницу небезопасной)
- **Service Worker** не работает: работа без сети и обновление со старой версии (v61.3 → v62) здесь не проверяются —
  они проверены автотестами (Chromium) и проверяются на опубликованном сайте (HTTPS, после выпуска).
- **Clipboard API** недоступен: «Скопировать ID» работает запасным способом (копирование выделенного ID) — тот же,
  что на старых iOS. Основной способ (Clipboard API) проверяется на опубликованном сайте.
