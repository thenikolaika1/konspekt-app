# Выпуск Friends & Family: применение 5 миграций и откат

Папка `supabase/release/` — всё для безопасного применения миграций F&F к production и для отката.
Миграции применяет только владелец, по шагам ниже. Пароль базы вводится только у вас на компьютере
и никому не передаётся.

## Файлы

| Файл | Что делает | Меняет базу? |
|---|---|---|
| `apply-ff-migrations.ps1` | применяет 5 миграций по порядку, каждую отдельной транзакцией, с проверками до и после | да (кроме `-CheckOnly`) |
| `precheck.sql` | база в ожидаемом состоянии до миграций | нет |
| `status.sql` | какие из 5 миграций уже применены | нет |
| `counts.sql` | число строк в таблицах пользователей | нет |
| `fingerprint.sql` | построчное описание структуры существующих таблиц (без данных) | нет |
| `postcheck.sql` | всё на месте после миграций: бюджет AI = 0, права, справочник 77, отчёты | нет |
| `ai-stop.sql` | экстренно выключить AI (библиотека работает) | да |
| `rollback-2026101113-disable-analytics.sql` | отключить сбор аналитики, данные остаются | да |
| `rollback-20261011120500.sql` | откат нормализации кодов (кириллица) | да |
| `rollback-20261011120000-functions.sql` | вернуть функции F&F к состоянию до миграций (под Edge v19) | да |

Порядок миграций (скрипт соблюдает сам): `20261011120000` → `20261011120500` → `20261011130000` →
`20261011130100` → `20261011130200`. Edge Function v20 — **только после** всех пяти.

## Что должно быть готово заранее

1. Резервная копия production проверена (блокер B1).
2. Установлены PostgreSQL 17 Command Line Tools (у вас уже есть — ими сделан `pg_dump`).
3. Папка репозитория (ветка с этой папкой) на компьютере.
4. Пароль базы (Dashboard → Database → Settings; при сбросе подождать 1–2 минуты).
5. Адрес Session pooler: Dashboard → **Connect** → **Session pooler** → из строки подключения взять
   только адрес сервера вида `aws-0-…pooler.supabase.com` (пароль из строки не копировать).

## Шаги в PowerShell

**1. Открыть PowerShell в папке репозитория** (Проводник → папка → в адресной строке набрать
`powershell` → Enter). Разрешить запуск скриптов только для этого окна:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
Get-ChildItem .\supabase\release\*.ps1 | Unblock-File
```

**2. Пробный запуск без изменений** (вместо `АДРЕС` — адрес Session pooler):

```powershell
.\supabase\release\apply-ff-migrations.ps1 -DbHost АДРЕС -CheckOnly
```

Ожидаемо: `psql: … 17.x`, пять строк SHA-256, `Подключение: postgres…|postgres|17.x`, `PRECHECK OK`,
пять строк `к применению: …`, `Режим -CheckOnly: изменений не было.`
Пароль скрипт спросит сам — символы не отображаются, это нормально.

**3. Применение** (та же команда без `-CheckOnly`):

```powershell
.\supabase\release\apply-ff-migrations.ps1 -DbHost АДРЕС
```

Скрипт покажет список и попросит ввести `APPLY` (латиницей, заглавными). Ожидаемо: `[1/5] … OK` …
`[5/5] … OK`, затем `POSTCHECK OK: … бюджет AI = 0 …`, `Число строк: потерь нет`,
`Структура существующих таблиц, права и политики: без изменений.`, `ГОТОВО`.
Строки `больше: auth.users …` — это новые посетители во время работы, не ошибка.

Все результаты — в папке `ff-release-ДАТА-ВРЕМЯ` (паролей и данных пользователей там нет).

**4. Сразу после**: открыть приложение — библиотека и профиль на месте; генерация конспекта покажет
«AI на паузе» (бюджет 0) — так и должно быть до решения по бюджету.

## Если что-то пошло не так

- **`СТОП: ошибка в <миграция>`** — эта миграция откатилась целиком, следующие не запускались, база
  в согласованном состоянии. Ничего не запускайте повторно — пришлите текст ошибки (без паролей).
- **`СТОП: precheck не пройден`** — подключение не к той базе или неожиданное состояние; ничего не изменено.
- **`СТОП: неожиданное состояние`** — миграции применялись не по порядку; ничего не изменено.
- **`ПОТЕРЯ:` или `структура … изменилась`** — миграции уже применены, но проверка нашла отличие;
  ничего не делайте, пришлите вывод.
- Скрипт можно запускать повторно: применённые миграции он пропускает и продолжает с первой
  неприменённой.

## Откат (только по решению владельца, в обратном порядке)

Каждый файл — одной транзакцией, с остановкой на первой ошибке. Пароль спросит `psql`.
Переменные подключения задать один раз в окне:

```powershell
$env:PGHOST='АДРЕС'; $env:PGPORT='5432'; $env:PGUSER='postgres.ohdeykbkgimvwstkwuuf'; $env:PGDATABASE='postgres'; $env:PGSSLMODE='require'
```

0. Экстренно выключить AI: `psql -X --single-transaction -v ON_ERROR_STOP=1 -f .\supabase\release\ai-stop.sql`
1. Если уже задеплоена Edge v20 — вернуть v19 (копия есть; деплой отдельно).
2. Отключить аналитику (данные остаются): `… -f .\supabase\release\rollback-2026101113-disable-analytics.sql`
3. Откат нормализации кодов: `… -f .\supabase\release\rollback-20261011120500.sql`
4. Откат функций F&F под v19: `… -f .\supabase\release\rollback-20261011120000-functions.sql`

Откаты не удаляют данные пользователей. Таблицы `private.ai_limits` и `analytics.*` остаются (в них только
настройки и собранная аналитика). Вернуть нормализацию после шага 3 — выполнить файл миграции
`20261011120500` тем же способом.

## Аккаунты участников: вход по ID и ключу (сайт v57)

Каждому участнику — свой ID (`KN-XXXXXX`) и отдельный ключ (20 символов). Алфавит без O, I, L, 0, 1.
Приложение ничего не заменяет само: ID и ключ вводятся как выданы (регистр, пробелы и дефисы не важны).

1. Создать аккаунты (Supabase Auth, Admin API). Ключ `service_role` — из Dashboard → Project Settings → API;
   скрипт спросит его скрыто (или возьмёт из `$env:KONSPEKT_SERVICE_ROLE_KEY`) и нигде не сохранит.
   Папка результатов — **вне репозитория** (скрипт откажется работать внутри него):

   ```powershell
   .\supabase\release\ff-accounts.ps1 -Count 12 -OutDir C:\Users\me\Documents\ff-accounts
   ```

   Результат: `ff-accounts-*.csv` (ID, ключ, uid — **секрет**, раздать каждому его строку лично),
   `entitlements-*.sql` и `verify-*.sql` (только uid и ID, без ключей).
2. Выполнить `entitlements-*.sql` (SQL Editor или `psql -X -v ON_ERROR_STOP=1 -f …`). Ожидается
   `NOTICE: OK: N участникам назначено beta_invite, quota 1`. SQL проверяет результат сам и откатывается, если
   аккаунт не найден, у пользователя уже есть право (у существующего права `source` не меняется) или итог не совпал.
3. Выполнить `verify-*.sql`: N строк, у всех `ok = true`.

Окно F&F для `beta_invite` и общие лимиты задаются в `private.ai_limits` отдельно; скрипт их не меняет.
