## Почему выпуск — одним окном

Три шага зависят друг от друга. Между ними новый ученик оказывается в неполном состоянии:

| Окно | Что видит НОВЫЙ ученик (регистрация после шага 1) | Старые аккаунты |
|---|---|---|
| после шага 1, до шага 2 | пробный период выдан и уже идёт, но старая `analyze-pages` (v24) отказывает в генерации (`ACCESS_EXPIRED`) | без изменений |
| после шага 2, до шага 3 | генерация работает, но приложение v59 показывает «Бесплатные конспекты закончились» | без изменений |

Поэтому: **все три шага подряд, за одно короткое окно (≈ 30 минут), и никаких новых приглашений с начала окна до конца проверки.**
Существующие аккаунты в окне не затрагиваются (проверено тестами: старый `get_my_access` отвечает им одинаково до и после миграции).

## Новый ученик, приглашённый до выпуска (через v59)

С 24.10 окно F&F (`ai_limits.beta_ends_at`) закрыто. Ученик, зарегистрированный по старой системе **до** миграции:
- получает обычный аккаунт с ID, личные конспекты и библиотеку в v59, но **ИИ ему недоступен** (сервер: окно F&F закрыто; v59 показывает «Бесплатные конспекты закончились»);
- после миграции его аккаунт не меняется: выдач нет, статус `expired / legacy`; v61 покажет «Бесплатное тестирование завершено». Пробный период автоматически **не** выдаётся (триггер срабатывает только при регистрации);
- данные (аккаунт, конспекты, закладки) сохраняются — проверено тестами.

Варианты (решает владелец):
1. **Пригласить после выпуска** — пробный период выдастся автоматически. Проще всего.
2. **Пригласить сейчас, пробный — при выпуске:** после шага 3 `select private.admin_grant_trial('KN-XXXXXX', 'приглашён до v61');` — 7 дней и 1 генерация с этого момента (один раз на аккаунт).
3. **Не рекомендуется:** продлить окно F&F в `ai_limits` — оно общее, ИИ снова откроется и 7 прежним тестировщикам.

## Защита бюджета ИИ

Неудачный запуск (ошибка или функция прервалась) **не тратит** генерацию ученика, но тратит общий бюджет (`ai_limits.total_starts`). Поэтому для всех, кроме владельца:

| Настройка `private.access_settings` | По умолчанию | Смысл |
|---|---|---|
| `max_failed_per_grant` | 3 | неудач за срок доступа — не больше max(этого числа, лимита генераций срока) |
| `max_failed_per_day` | 2 | неудач за последние 24 часа |
| `max_starts_per_day` | NULL (нет) | всех запусков за 24 часа |

Идущие запуски (итога ещё нет) при проверке пределов считаются возможными неудачами — параллельные запуски предел не обходят.

Отказы — `RETRY_LIMIT` («Слишком много неудачных попыток») и `DAILY_LIMIT` («На сегодня запуски ИИ закончились»). Владелец: только общие лимиты (`ai_limits`).

**Предлагаемая конфигурация для закрытого тестирования (бюджет 40):**
```sql
update private.access_settings set max_failed_per_grant = 3, max_failed_per_day = 2, max_starts_per_day = 3, updated_at = now() where id;
```
Пробный ученик в худшем случае тратит 1 успешный + 3 неудачных = 4 запуска за 7 дней. Оплаченный срок с лимитом N — не больше N + max(3, N) запусков и не больше 3 в сутки.
Общий бюджет 40 (занято 7) хватит примерно на 8 пробных учеников в худшем случае; перед продажей платных сроков бюджет нужно пересмотреть (отдельное решение владельца).

## Ручное управление (SQL Editor)

```sql
-- что у участника сейчас: статус, все сроки с использованием и неудачами, журнал
select private.admin_status('KN-XXXXXX');

-- первая оплата: доступ с этого момента; срок и генерации — явно или из тарифа (private.plans)
select private.admin_grant('KN-XXXXXX', null, 30, 20, 'оплата 01.11');
select private.admin_grant('KN-XXXXXX', 'код_тарифа', null, null, 'оплата 01.11');

-- продление: с конца текущего срока (заранее — время не теряется) или с этого момента (после окончания);
-- у нового срока свой лимит, остаток прежнего не переносится
select private.admin_extend('KN-XXXXXX', null, 30, 20, 'продление');

-- отзыв действующего и будущих сроков (строки и журнал остаются). Если ещё идёт пробный период —
-- ученик продолжит его до конца (без новых дней и без возврата использованных пробных генераций)
select private.admin_revoke('KN-XXXXXX', 'причина');

-- пробный период вручную (например, ученик из F&F или приглашённый до v61) — один раз на аккаунт
select private.admin_grant_trial('KN-XXXXXX', 'перенос');
```

Тарифы для экрана «Тарифы» (видны только `active = true`; цена — только если задана):
```sql
insert into private.plans (code, title, days, ai_quota, price_label, description, active)
values ('…', '…', 30, 20, null, null, true);
```

## Ограничения

- Экран «Доступ закончился» — интерфейс. Генерацию ИИ закрывает сервер, а тексты библиотеки лежат в публичном `js/library-catalog.js` и экраном не защищены.
- Общий бюджет ИИ (`ai_limits.max_total_starts` = 40) общий для всех, включая владельца.
- Повторная регистрация по новому приглашению даёт новый пробный период — организационный риск (коды выпускает владелец).
- Папка `tests/` публикуется на сайте вместе с остальными файлами репозитория (секретов в ней нет; репозиторий и так публичный).
