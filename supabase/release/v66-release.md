Каждый шаг публикации выполняется только после отдельного разрешения владельца.

## 1. Что входит

| Часть | Что меняется | Файлы |
|---|---|---|
| Защита текста | выделение, копирование (Ctrl/Cmd+C, Ctrl+Insert, Ctrl/Cmd+X, «Копировать»), Ctrl/Cmd+A/S/P, контекстное меню, перетаскивание и печать в области конспекта выключены у всех, кроме владельца; на обоих экранах (свой конспект и параграф библиотеки); поля ввода не затронуты | `js/protect.js` (новый), `styles.css` (+6 правил), `app.js`, `index.html` |
| Водяной знак | один небольшой полупрозрачный код `KN-XXXXXXXX` у нижнего края видимой части конспекта; код = первые 8 знаков SHA-256("konspekt-wm:" + id аккаунта); без email и телефона | `js/protect.js`, `styles.css` |
| Поиск | в конспекте и в «Все конспекты»: неразрывный пробел после однобуквенных слов, ё = е, лишние пробелы | `app.js` |

промптов, тарифов, лимитов, доступа, дизайна. Миграция ограничения библиотеки — отдельное решение (раздел 5).

## 2. Найденное расхождение с production

Развёрнутая `analyze-pages` v33 (ezbr `3308dd14…`) содержит `MAX_PAGES = 8` и `OWNER_PAGE_TEST = true`: **владелец
может запустить генерацию 5–8 фото** (в обход `private.ai_limits.max_pages = 4`). У остальных пользователей база
отказывает (`too_many_pages`). Исходный код v33 лежит в ветке отдельным коммитом (`dab1677`, совпадает с production
побайтно); исправление — следующий коммит (`MAX_PAGES = 4`, `OWNER_PAGE_TEST = false`). Тест
`tests/v66r/release-analyze.test.ts` на исходной v33 даёт 6 FAIL (владелец 5/6/8 фото — 202 и вызов ИИ), на исправленной —
60/60. Для ≤ 4 фото путь генерации v33 не меняется (один запрос, без частей).

В репозитории `main` лежит более старый код `analyze-pages`, чем развёрнутый v33: после выпуска `main` будет совпадать
с production.

  подсветка и «1 из N»; поиск в «Все конспекты» работает.

- Логи функции: нет новых ошибок.

## 5. Миграция ограничения библиотеки (отдельное решение)

аккаунт; перечитывание за последние сутки бесплатно; владелец без ограничений. Откат —
`…library_rate_limit.rollback.sql` (теряется только служебный журнал чтений). Проверено на локальной копии:
`tests/v66r/rate-limit.test.sh`. Применять — `apply_migration` с текстом файла; проверка после — вызов

## 6. Откат

- Сайт: `git revert -m 1 <merge-коммит>` в `main` (или PR с ним). Номер сборки снова 65 ≠ 66 — открытые приложения
  перезагрузятся, service worker v65 удалит кэш v66. Конспекты учеников хранятся в базе и на устройстве — не затрагиваются.
- Сервер: развернуть `analyze-pages` из коммита `dab1677` (точная копия v33) или из `backup/analyze-pages-v33-production.tar.gz`.
- Миграция (если применялась): `…library_rate_limit.rollback.sql`.

## 7. Чего защита не делает

Не запрещает скриншоты и съёмку экрана, распознавание текста со снимка, чтение уже загруженной страницы через
инструменты разработчика. Она убирает простое копирование и помечает снимки экрана кодом аккаунта.
