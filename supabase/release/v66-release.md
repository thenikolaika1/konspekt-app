## 6. Откат (данные учеников не затрагиваются ни одним шагом)

Выпуск не меняет базу: конспекты, история, доступы и оплаты остаются как есть при любом откате.
- **Сайт:** `git revert -m 1 <merge-коммит>` в `main` (или PR с ним), дождаться публикации Pages. Номер сборки снова
  65 ≠ 66 — открытые приложения перезагрузятся, service worker v65 удалит кэш v66.
- **`analyze-pages`:** развернуть 6 файлов из коммита `dab1677` (`supabase/functions/analyze-pages`, точная копия
  production v33/v35, ezbr `3308dd14…`), `verify_jwt: false`; сверить SHA-256.
- **`register-invite`:** развернуть файл из `main` (`47fccfc`), `verify_jwt: false`.
- Проверка после отката — та же команда из шага 3 публикации (`401 UNAUTHORIZED`).
- Миграция библиотеки (если когда-нибудь применят): `…library_rate_limit.rollback.sql`.

Резервные копии (13.11): код функций production и база (схема, данные без паролей и секретов, тексты библиотеки) —
вне репозитория, у разработчика; код — также в git (`main` = сайт v65, `dab1677` = `analyze-pages` v33/v35).

## 7. Чего защита не делает

Не запрещает скриншоты и съёмку экрана, распознавание текста со снимка, чтение уже загруженной страницы через
инструменты разработчика. Она убирает простое копирование и помечает снимки экрана кодом аккаунта.
