# Доступ из России без VPN: прокси к Supabase

С июня 2025 года крупные российские провайдеры (Ростелеком, МТС, МегаФон, Билайн, МГТС) обрывают
соединения с адресами Cloudflare (и Hetzner, DigitalOcean, OVH) после ~16 КБ. Supabase работает через
Cloudflare, поэтому без VPN не загружаются фото и не скачиваются готовые конспекты; мелкие запросы проходят.
В логах production это видно: 08.10 с российского IP создалась note (174 байта), но ни одна загрузка
фото (~600 КБ) не дошла; 09.10 через VPN те же фото загрузились за 1,3 с.

Решение: все запросы приложения к Supabase идут через прокси на площадке, доступной из России.
Прокси прозрачный — Auth, RLS, Storage, Edge Functions и лимиты не меняются, сессии пользователей те же.

## Вариант A — Yandex API Gateway (без сервера)
1. Yandex Cloud → API Gateway → создать шлюз, спецификация — `yandex-api-gateway.yaml`.
2. Адрес шлюза (`https://<id>.apigw.yandexcloud.net`) вписать в `js/config.js`: `routes: { ru: "…" }`.
3. Цена: до 100 тыс. запросов и 100 ГБ исходящего трафика в месяц бесплатно, дальше около $1 за 1 млн запросов.
4. Ограничение: запрос + ответ не больше 2,5 МБ.

## Вариант B — VPS с nginx
1. Небольшой VPS (несколько сотен рублей в месяц) + домен + Let's Encrypt.
2. Конфигурация — `nginx.conf`; адрес — в `routes.ru`.

## Проверка до переключения всех
1. На iPhone без VPN, в российской сети, открыть приложение с `?route=ru` (маршрут запоминается на устройстве).
2. Сделать один конспект: фото должны загрузиться, конспект — открыться.
3. Вернуть прямой маршрут на устройстве: `?route=direct`.
4. Если всё работает — `route: "ru"` в `js/config.js` для всех.

Перед выбором площадки: замедление действует по адресу назначения; работает ли исходящий трафик
конкретной площадки к Cloudflare без обрывов — проверяется только этим тестом.

## Безопасность
- Прокси видит запросы в открытом виде (токены, фото) — это наша инфраструктура; журнал запросов выключен.
- В приложении маршрут выбирается только из списка в `config.js`: подставить свой адрес ссылкой нельзя.
- Лимиты Supabase Auth считаются по IP: через прокси все пользователи приходят с одного адреса.
  Лимит на создание анонимных пользователей (по умолчанию 30 в час) нужно поднять в Supabase Dashboard
  → Authentication → Rate Limits.
